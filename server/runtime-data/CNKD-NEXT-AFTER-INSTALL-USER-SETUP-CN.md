# CNKD NEXT 服务端安装后使用指南

> 适用范围：CNKD NEXT 单房间 Start 服务端
>
> 适用对象：已经完成服务端安装、可以打开实例控制台的服主
>
> 详细总指南：仓库中的 `docs/CNKD-NEXT-USER-GUIDE-CN.md`，或部署包根目录的 `CNKD-NEXT-USER-GUIDE-CN.md`

> [!NOTE]
> 当前文档已同步单房间 `1.1.6-BattleRoom-Test` 构建基线。它说明的是使用者可见行为，不代表排位平台或 Relay 专用部署。

## 当前版本重点

本版本重点收口了长期运行中最容易影响玩家体验的生命周期链路：

- `.battleroom` 和自动返回战役室后，服务端会阻断上一局残留的游戏同步和单位操作。
- 返回大厅会清理已失效的断线人类玩家，避免槽位阻塞第二局。
- 恢复过程完成两轮轻量大厅刷新后才允许再次开局。
- 自定义地图开始包会在开局前验证，地图数据异常时不会发送不完整开始包。
- 原版核心静默拒绝开始时，开局确认看门狗会在限定时间后释放开始锁。
- `reloadmaps`、`reloadmods` 和地图缓存清理在对局、返回和恢复期间会被拒绝。

建议连续开局前等待大厅玩家列表和地图状态稳定；出现异常时优先保留 `startmode diagnose` 和 `lowlatency readout` 输出。

## 使用前说明

本指南只说明服务端安装完成后的配置、地图、模组和房间管理操作，不涉及实例创建、系统安装或端口申请。

服务端有两类命令入口：

- **控制台命令**：直接输入到服务端控制台，不要加 `.`。
- **游戏内命令**：在游戏聊天栏输入，以 `.` 开头，例如 `.maps`。

命令中的“位置”是玩家槽位号。控制台 `players`、`admin add`、`kick` 等命令使用从 **1** 开始的位置号；游戏内 `.maps` 列表中的地图编号从 **0** 开始。

## 快速开始

首次启动或完整重启后，建议按以下顺序检查：

```text
version
```

```text
players
```

```text
maps
```

如果已上传模组或地图，先完成本指南的“上传自定义地图和模组”部分，再让玩家进入房间。

游戏开始、换图、加 AI 等大厅操作由房主和管理员权限控制。玩家可在游戏内输入：

```text
.help
```

查看当前客户端可用命令及其参数。

## 基础配置与可视化配置

主配置文件为：

```text
data/ServerConfig.json
```

优先检查以下项目：

| 配置项 | 用途 | 默认建议 |
| --- | --- | --- |
| `common.serverName` | 房间与列表显示名称 | 修改为自己的服务器名称 |
| `common.chatSenderName` | 游戏聊天栏中的服务器提示名称 | 使用简短中文或英文名称 |
| `gameplay.maxPlayer` | 最大玩家数 | 默认 100，按地图人数下调 |
| `gameplay.maxUnit` | 单名玩家单位上限 | 默认 1000，大型模组可适当下调 |
| `gameplay.enableAI` | 是否允许添加 AI | 娱乐服按需开启 |
| `gameplay.startMinPlayerSize` | 手动开局最低人数 | `-1` 表示不限制 |
| `gameplay.autoStartMinPlayerSize` | 自动开局人数 | `-1` 表示关闭自动开局 |
| `map.enableMapLock` | 是否锁定地图 | 普通服建议关闭 |
| `map.lockMap` | 锁定地图名称 | 仅在锁图时填写 |
| `common.errorLogMaxSizeMb` | 单个核心错误日志大小 | 默认 8 MB |
| `common.errorLogRetainFiles` | 错误日志历史文件数 | 默认 3，总默认约 32 MB |

修改配置后有两种生效方式：

```text
reloadconfig
```

或在实例控制台停止服务端后再次开启。

涉及端口、启动内存、Netty worker、模组加载等启动期项目时，请使用完整停止后再开启；`reloadconfig` 不能重建网络监听和已加载模组。

### 可视化配置文件

公共列表支持包可配合以下可视化配置描述文件使用：

```text
CNKD-NEXT-PublicList-VisualConfig.json
```

它用于支持可视化配置导入的管理工具，实际修改目标仍是：

```text
data/ServerConfig.json
```

可视化配置适合编辑服务器名称、人数、单位上限、AI、自动开局、地图锁定、公共列表、低延迟档位、控制台输出和插件日志等项目。

注意：可视化配置文件不是地图或模组，不能上传到 `data/maps` 或 `data/mods`。公共列表开关只在支持 UPLIST 的发布包中有效；禁 UPLIST 包即使配置为开启也不会公开。

## 上传自定义地图和模组

在实例管理后台按以下路径操作：

```text
实例控制台 → 文件管理 → data
```

然后根据文件类型上传：

| 内容 | 上传目录 | 常见格式 |
| --- | --- | --- |
| 普通自定义地图 | `data/maps` | `.tmx`、地图压缩包 `.zip` |
| 模组 | `data/mods` | `.rwmod`、模组压缩包 `.zip` |

### 上传普通地图

1. 将 `.tmx` 地图上传到 `data/maps`。
2. 在没有对局进行时执行：

```text
reloadmaps
```

3. 让房主或有权限的管理员在游戏内执行：

```text
.maps
```

4. 根据列表中的编号选择地图，例如选择编号 `0`：

```text
.map 0
```

### 上传模组

1. 将 `.rwmod` 或模组 `.zip` 上传到：

```text
data/mods
```

2. 推荐直接在实例控制台终止服务端后再次开启。这是加载新模组最完整、最稳定的方式。
3. 如果当前没有对局，且只需要尝试重新读取文件，可依次执行：

```text
reloadmods
```

```text
reloadmaps
```

4. 使用以下命令检查模组与地图识别结果：

```text
mods
```

```text
maps
```

### 模组地图自动识别

默认已开启模组地图发现和自动准备功能。服务端会扫描 `data/mods` 中的 `.rwmod`、`.zip` 和已解压模组目录，识别模组内符合 `mod-info.txt` 的 `[maps] sourceFolder` 配置的 `.tmx` 地图。

因此，模组自带地图通常只需要上传模组本体，不需要再手动从模组中提取地图上传到 `data/maps`。

服务端会将运行所需的模组地图和支撑资源准备到：

```text
data/maps/cnkd_mod_maps
```

这是服务端管理的运行缓存，请不要在服务运行时手动移动、修改或删除其中内容。更换或删除模组后，执行 `reloadmaps` 或完整重启，服务端会按安全策略回收失效缓存。

> [!IMPORTANT]
> 玩家客户端必须安装相同模组，才能正确进入模组地图并加载单位、贴图和音效。服务端能自动识别模组地图，但不能把玩家本地缺失的模组发送给客户端。

## 控制台常用命令

以下命令直接输入服务端控制台，不加 `.`。

### 查看在线玩家

```text
players
```

显示当前在线人数、保留槽位、短线重连保护人数，以及每名在线玩家的位置、名称和网络信息。

执行任何按位置管理的命令前，先执行 `players` 确认目标位置。

### 设置超级管理员

```text
admin add <玩家位置>
```

示例，将 `players` 输出中位置为 `1` 的玩家设为超级管理员：

```text
admin add 1
```

该命令只能在大厅使用，不能在对局中执行。成功后，该玩家获得超级管理员身份和客户端 HOST 标识。默认配置下，运行期变更会写入 `data/PersistentAccessConfig.json`，玩家下次进入仍可恢复身份。

移除超级管理员：

```text
admin remove 1
```

`admin add` 授予的是 **超级管理员**，不是普通临时房主。超级管理员默认不占用普通房主分配，并受 `RoomPermissionConfig.json` 中的 `superAdminBypass` 与管理员权限规则影响。

### 查看管理员

```text
admins
```

显示已记录的管理员 UUID、名称、普通管理员与超级管理员状态。

### 重新读取地图

```text
reloadmaps
```

重新扫描 `data/maps`，同时扫描 `data/mods` 中可识别的模组地图，并重新应用已启用的锁图配置。上传、替换或删除地图/模组后建议执行。

如果模组刚上传，优先完整重启；只执行 `reloadmaps` 不能替代模组本体加载。

### 重新加载模组

```text
reloadmods
```

仅能在大厅执行。用于重新读取 `data/mods` 中的模组。执行后再运行 `reloadmaps`，使模组自带地图进入地图列表。

### 查看已加载模组

```text
mods
```

```text
mods status
```

`mods` 显示模组列表；`mods status` 显示模组地图扫描、自动提取和兼容性诊断。

### 查看自定义地图列表

```text
maps
```

```text
maps 2
```

显示服务端已识别的自定义地图和模组地图；地图较多时可指定页码。

### 全服公告

```text
say <内容>
```

示例：

```text
say 服务器将在五分钟后维护
```

### 配置重载与健康检查

```text
reloadconfig
```

```text
configcheck
```

```text
health detail
```

`reloadconfig` 读取主配置；`configcheck` 检查配置风险；`health detail` 查看内存、存储、房间和运行建议。

### 其他常用管理命令

| 命令 | 用途 | 使用提示 |
| --- | --- | --- |
| `say <内容>` | 全服公告 | 不影响对局流程 |
| `whisper <位置> <内容>` | 私聊指定玩家 | 先用 `players` 确认位置 |
| `ban <位置>` | 封禁玩家 | 谨慎使用，属于持久管理操作 |
| `unban <位置>` | 解除指定在线玩家封禁 | 玩家需在线 |
| `mute <位置> [秒]` | 禁言玩家 | 未填写时使用默认时长 |
| `kick <位置>` | 大厅踢出玩家 | 对局中不建议使用 |
| `giveadmin <位置>` | 转移普通房主 | 不会撤销超级管理员 |
| `gameover` | 强制重置当前房间 | 对局异常时使用，所有玩家会受影响 |
| `save` | 保存当前对局 | 仅对局中可用 |
| `mapgc status` | 查看模组地图运行缓存 | 日常查看即可 |
| `mapgc cleanup` | 回收可安全删除的模组地图缓存 | 建议在大厅使用 |
| `maintenance plan` | 查看缓存、回放和日志清理建议 | 默认只预览，不删除文件 |

## 游戏内常用命令

以下命令输入游戏聊天栏，并使用 `.` 前缀。

### 查看帮助

```text
.help
```

显示当前客户端可用命令。命令是否可用取决于房主、管理员和 `RoomPermissionConfig.json` 权限配置。

### 查看和选择地图

```text
.maps
```

```text
.maps 2
```

显示可选自定义地图和模组地图。选择列表中的编号：

```text
.map 0
```

切换回默认内置地图：

```text
.map def
```

`.map` 只能在大厅使用。启用 `map.enableMapLock=true` 后，地图锁定优先，游戏内命令不会绕过锁图。

### 开始与返回大厅

```text
.start
```

```text
.battleroom
```

`.start` 在大厅请求开始游戏；`.battleroom` 在对局中返回战役室。返回完成后请等待大厅状态同步完成，再开始下一局。

### 玩家与队伍操作

```text
.give <玩家位置>
```

```text
.t2
```

```text
.t3
```

```text
.tffa
```

```text
.tv
```

`.give` 转移普通房主；`.t2` 分两队；`.t3` 分三队；`.tffa` 设置混战；`.tv` 将全员设为观战。上述操作会按当前房间权限和观战状态执行。

### 其他实用命令

| 命令 | 用途 |
| --- | --- |
| `.status` | 查看房间服务端状态 |
| `.myid` | 查看自己的身份 ID，用于持久管理员配置 |
| `.surrenderstatus` | 查看当前团队投降进度 |
| `.ffa` | 切换混战队伍逻辑 |
| `.teamlock on` | 锁定普通玩家的队伍和位置调整 |
| `.teamlock off` | 解除队伍和位置锁定 |
| `.pause` / `.unpause` | 暂停或恢复对局 |

原版投降按钮仍可正常使用。默认团队投降模式会显示团队申请进度；启用单人投降模式后，投降会直接按原版流程处理。

## 权限与房主说明

权限配置文件为：

```text
data/RoomPermissionConfig.json
```

常见角色：

| 角色 | 用途 |
| --- | --- |
| 普通玩家 | 使用被允许的查看、投票和自助功能 |
| 普通房主 | 管理大厅、开始游戏、换图、设置房间参数 |
| 管理员 | 按 `admin` 权限组执行房间管理 |
| 超级管理员 | 由控制台 `admin add` 或持久权限配置授予，可按 `superAdminBypass` 规则绕过房间动作限制 |

如果需要长期添加管理员，先让玩家进入服务器并输入：

```text
.myid
```

再按 `data/PersistentAccessConfig.json` 中的示例填写 UUID。不要只依赖玩家昵称，真正的权限匹配使用 UUID。

## 日常维护

推荐日常操作顺序：

1. 执行 `players`，确认是否有人在线。
2. 上传地图或模组前，避免在对局进行时修改文件。
3. 上传后，优先完整停止并再次开启服务端；无对局时也可以执行 `reloadmods` 和 `reloadmaps`。
4. 使用 `mods status`、`maps` 或 `.maps` 确认识别结果。
5. 修改普通配置后执行 `reloadconfig`；修改启动期配置后完整重启。
6. 发现卡顿、同步或开局异常时，先执行：

```text
startmode diagnose
```

```text
lowlatency readout
```

```text
lowlatency summary
```

7. 正常长期运行时，保持 `common.log=WARN`。核心错误日志默认轮转为 `Log.txt`、`Log.txt.1`、`Log.txt.2`、`Log.txt.3`，总默认约 32 MB。

## 常见问题

### 上传模组后地图没有出现

依次确认：

1. 模组文件位于 `data/mods`，而不是 `data/maps`。
2. 模组包含 `.tmx` 地图，并在 `mod-info.txt` 的 `[maps] sourceFolder` 中声明地图目录，或使用默认 `maps/` 目录。
3. 重新启动服务端，或在大厅执行 `reloadmods` 后执行 `reloadmaps`。
4. 执行 `mods status` 查看是否因文件过大、压缩包损坏或扫描错误被跳过。
5. 玩家客户端安装了同一模组。

### `.maps` 有地图但无法切换

确认当前不在对局中，并检查：

- 操作者是房主或管理员，且有换图权限。
- `map.enableMapLock` 未锁定其他地图。
- `.map` 使用的是 `.maps` 列表中从 0 开始的编号。

### `admin add` 无法执行

确认：

- 当前在大厅，不在对局中。
- 使用了 `players` 输出中的正确位置号。
- `RoomPermissionConfig.json` 没有关闭 `allowManualAdminGrantFromConsole`。

### 修改配置后没有变化

普通配置先执行：

```text
reloadconfig
```

端口、模组、地图、本地网络线程和启动参数等项目需要完整停止后再开启服务端。

### 服务端日志占用空间持续增长

当前核心错误日志默认总上限约 32 MB。若仍发现磁盘占用增长，执行：

```text
health detail
```

检查回放、缓存、模组地图运行目录和插件日志；再使用：

```text
maintenance plan
```

查看可安全清理的内容。不要在服务运行时直接删除当前正在使用的地图、模组或日志文件。
